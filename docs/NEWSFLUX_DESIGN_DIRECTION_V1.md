# NewsFlux Design Direction V1

- **Status:** design gate for Phase 2B.2; this document does not authorize implementation of the future IA or visual system.
- **Reviewed:** 2026-10-10.
- **Critical reference viewport:** 884 × 1104 (open foldable/tablet).

## Product direction

The visual direction combines an OLED-aware canvas, editorial content hierarchy, predictable Material-style interaction feedback, and Liquid Glass-inspired navigation chrome. The reading surface and story cards remain opaque, quiet content surfaces; translucency belongs to controls that float above content. News, rather than decoration, owns the strongest contrast and largest type.

The current Miniflux integration remains the source of truth for feed catalog, categories, read/unread state and starred state. The current `all`, `today`, `starred`, `history`, feed and category scopes remain the available product data. Any new saved-item type needs an explicit storage and sync decision before implementation.

### Liquid Glass and interaction material

Glass is navigation chrome, never the default card background. Future tokens should include:

| Token role           | Starting direction                                                               |
| -------------------- | -------------------------------------------------------------------------------- |
| Fill                 | Neutral surface tint with enough opacity to preserve text and icon contrast.     |
| Blur                 | 16 px starting point, reduced or removed under reduced-transparency preferences. |
| Rim / highlight      | Fine upper edge and subtle specular highlight, not a bright outline.             |
| Edge                 | One low-contrast boundary to separate floating chrome from content.              |
| Inner highlight      | Soft top inset, limited to controls.                                             |
| Drop shadow          | Short, soft lift that reads over both dark and image content.                    |
| Pressed              | Short-lived state layer; keep label/icon and target stable.                      |
| Focus                | Persistent high-contrast outline independent of glass tint.                      |
| Reduced transparency | Opaque `surface-raised` fallback with the same hierarchy and hit target.         |

Preferred future surfaces are top controls, search, filter pill, floating article actions, bottom navigation, transient new-items indicator and context menus. Use Material as a reference for predictable target size, state layers and reduced-motion-aware transitions, not as a generic theme. Start motion at 160–220 ms; honor `prefers-reduced-motion` and app accessibility settings.

### Imagery and story states

- Keep a 16:9 editorial frame. Use `cover` for source ratios in the accepted editorial range and `contain` against a neutral media surface for vertical/extreme ratios.
- A missing/failed image yields a text-first card; do not insert a large broken-image placeholder.
- Unread: maximum title contrast, slightly stronger weight, a small consistent marker, normal image treatment, quiet metadata.
- Read: remove the unread marker, lower title weight and contrast moderately, quiet metadata, and optionally lower image saturation slightly. Keep all text readable and all actions visible.
- Hover, selected, keyboard-focus, starred, read and unread remain independently identifiable. Do not use global card opacity for read state; focus and selection require their own non-color affordance.

## Information architecture and state map

```text
Home (future editorial entry point; current home target can still be a view/feed/category)
├── All       → existing Miniflux all scope
├── Unread    → existing Miniflux unread status filter
├── Later     → future temporal reading queue; storage/sync decision required
├── Saved (future umbrella)
```
